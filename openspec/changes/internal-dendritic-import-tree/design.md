# Design: internal `import-tree` via vendoring

Change ID: `internal-dendritic-import-tree`
Companion: proposal.md, tasks.md
Research: `openspec/research/{import-tree.md, flake-parts-partitions.md, nix-oci-audit.md, nix-lib-current.md}`

## Decision record

### D1. Vendor rather than depend

Rejected: add `import-tree` as a flake input.

Rationale: Even under a partition (`partitions.dev.extraInputsFlake`),
the input is unreachable from `lib.*` outputs that consumers actually
call, because partitions cannot host `lib` outputs
(`research/flake-parts-partitions.md`). To use `import-tree` from
inside `flakeModules.default` or `flakeModules.pure` (which shape
consumer-facing outputs), the code path must not depend on partition-
only inputs.

Chosen: vendor `default.nix` from
`github:denful/import-tree` at a pinned commit. Cost is trivial:

- MIT license, one file, 268 lines, `builtins.*` only, zero deps
  (`research/import-tree.md`, "runtime-input finding" section).
- The tests file (`tests.nix`, 32 named cases) also serves as an
  executable spec if we need to refresh.

Location: `modules/nix-lib/_lib/import-tree/default.nix`.

Header (verbatim into the vendored file):
```
# Vendored from https://github.com/denful/import-tree
# Upstream commit: <PIN>
# Upstream license: MIT (LICENSE reproduced below).
# Do not edit this file locally. To refresh:
#   1. curl -L https://raw.githubusercontent.com/denful/import-tree/<PIN>/default.nix > default.nix
#   2. Update the pinned commit above.
#   3. Run the internal import-tree API tests.
```

### D2. Expose only as `_lib.importTree`

Rejected: expose `lib.importTree` under the public API.

Rationale: the user explicitly wants `import-tree` invisible to
consumers. Exposing it under `lib.*` invites usage from consumer flakes
and creates a hidden compatibility surface we would have to preserve.

Chosen: `modules/nix-lib/_lib/default.nix` imports the vendored file
and adds it to the internal factory record. The main flake never
merges it into `.lib` (see flake.nix's post-hoc `.lib =` merge).

```nix
# modules/nix-lib/_lib/default.nix (illustrative delta)
{ lib, ... }:
let
  importTree = import ./import-tree { };  # vendored, pure
  # ... existing evalLibModules, mkFlake, etc.
in
{
  inherit
    mkFlake evalLibModules mkSpecialArgsLib mkLib mkAdapter withLib;
  # importTree: internal-only, NOT re-exported into public lib.
  # Consumed via `let importTree = (import ./_lib { inherit lib; }).importTree; in ...`
  # or (better) via the module argument path when a flake module needs it.
  inherit importTree;
}
```

Because `nix-lib-outputs.nix` and other flake-parts modules run inside
`mkFlake`, we can also pass `importTree` via a private `_module.args`
so any flake module in `modules/nix-lib/*` can pull it without
re-importing.

### D3. Path handling under consumer eval

Key correctness question: when a consumer imports
`nix-lib.flakeModules.default`, does the tree walk resolve paths
against the consumer's flake or against nix-lib's own store path?

Answer: against nix-lib's own store path.

`import-tree ./modules/nix-lib` inside
`modules/nix-lib/_default.nix` resolves `./modules/nix-lib` against
the file that calls it. That file lives inside nix-lib's flake source
(a store path when consumed transitively). `builtins.readDir` walks
that store path at consumer eval time. This is transparent: no new
consumer input is needed, no fetch happens. The result is a flat
`imports = [ /nix/store/.../file1.nix /nix/store/.../file2.nix ... ]`
inside the module system, which merges just like a hand-written list.

Confirmed by `research/import-tree.md`, section on the two adoption
idioms and by inspection of `nix-oci` consumers whose own lock files
do not fetch nix-oci's `import-tree` dependency graph.

### D4. Convention for private files

`import-tree`'s default filter chain matches `.nix` suffix and skips
paths containing `/_` (a leading-underscore path segment)
(`research/import-tree.md`, "filters" section). We adopt the same
convention:

- `_lib/`, `_types/`, `_dev/`: whole subtrees hidden from discovery.
- Files with a leading `_` in their basename (`_default.nix`,
  `_pure.nix`, `_all.nix`, `_factory.nix`, `_markdown.nix`): hidden.
- Every other `.nix` file under a discovered directory becomes a
  live flake-parts module.

This matches nix-oci's `_nixos-oci/`, `_oci/` convention (see
`research/nix-oci-audit.md`).

### D5. Which lists to auto-discover

After discovery, the three current lists collapse into scoped calls.
Not all of them collapse to a single tree walk; some list distinct
subsets:

| Current file      | New discovery                                                              |
| ----------------- | -------------------------------------------------------------------------- |
| `_all.nix`        | `importTree ./nix-lib` filtered to `enable/namespace/testing/coverage/lib/internal` subtree (see D6) |
| `_default.nix`    | `importTree ./nix-lib` no filter (picks up docs/, legacyPackages/, tests/) |
| `_pure.nix`       | `importTree ./nix-lib` with a `filterNot` on `docs/`, `legacyPackages/`, `lib/perSystem.nix`         |
| `adapterDefs/default.nix` (imports) | `importTree ./builtins`                                          |

The **pure vs. full split** is the interesting design question, since
the whole point of `flakeModules.pure` is to be usable without pkgs.
Two ways to encode the split:

- **By path (chosen)**: `_pure.nix` calls `importTree` with a
  `filterNot` that excludes the pkgs-dependent subdirectories.
  Grep-visible, explicit, easy to review in a diff.
- Rejected: **by marker in each module** (each module declares
  `_pure = true;`). More invasive, requires a convention that lives
  in every file, and re-collects the same information the directory
  structure already encodes.

The `filterNot` for pure mode:
```nix
importTree.filterNot (path:
  builtins.any (needle: lib.hasInfix needle (toString path)) [
    "/docs/"
    "/legacyPackages/"
    "/lib/perSystem.nix"
  ]
) ./nix-lib
```

### D6. mkAdapter decoupling

Current: `mkAdapter.nix:237` says `imports = [ ../_all.nix ]`.

Proposed: mkAdapter takes an `imports` argument, defaulting to the
`importTree`-discovered core-option list (equivalent to today's
`_all.nix`).

```nix
# _lib/mkAdapter.nix (illustrative)
{ lib, importTree, ... }:
{ name, extraImports ? [ ], ... }:
let
  coreOptions = importTree { }
    ( it: it.match "^(enable|namespace|coverage|testing/|lib/internal)" )
    ../nix-lib;
in
{
  # ... existing mkAdapter body ...
  imports = [ coreOptions ] ++ extraImports;
}
```

Adapter modules stay callable exactly as today; the default is
identical to `_all.nix`'s current effect. An advanced consumer with
custom option modules can pass `extraImports` without needing to fork.

### D7. Dev partition auto-discovery

`modules/_dev/module.nix` gains an `importTree` call for the BDD
scenarios and (optionally) examples. This is inside the partition, so
it stays hidden from consumers even if we did add `import-tree` as a
partition-side input. But since we vendor, we can just reuse the same
vendored copy.

```nix
# modules/_dev/module.nix (illustrative delta)
{ inputs, ... }:
let
  importTree = import ../nix-lib/_lib/import-tree { };
in
{
  imports = [
    (importTree ../../tests/scenarios)
    (importTree ../../examples)
  ];
  # ...
}
```

If the scenario/example subflakes need special handling (they are
subflakes, not modules), we filter or transform via `importTree.map`.

### D8. Refresh policy

We pin a single commit hash. Refreshes are manual and gated on a
review that:
- Diffs the upstream file against the vendored copy.
- Runs the vendored `tests.nix` (which we also copy in for
  self-verification, at `_lib/import-tree/tests.nix`).
- Bumps the pinned commit.

Frequency: only when a specific upstream fix or feature is needed.
There is no CVE surface for a 268-line pure-Nix file.

## Alternatives considered and rejected

### A1. Add `import-tree` as a flake input under a partition

Attractive: no vendoring, refresh via `nix flake update`.

Fatal: the parts of nix-lib that need `import-tree` most (the three
lists that shape `flakeModules.*`) live in the main flake, not in a
partition. Partitions cannot host `lib.*` outputs. See D1 and
`research/flake-parts-partitions.md`.

### A2. Add `import-tree` as a top-level flake input (visible to consumers)

Attractive: simplest.

Fatal: violates the user's explicit constraint. Adds a lock entry to
every downstream flake.

### A3. Reimplement import-tree from scratch (not vendored)

Attractive: no license attribution to maintain.

Fatal: reinventing a well-tested 268-line library for aesthetic
reasons is bad ROI. Vendoring with attribution is standard practice.

### A4. Adopt dendritic-pattern layout wholesale (mightyiam/dendritic)

Attractive: canonical, well-documented.

Rejected for this change: too large a refactor. Preserves the existing
directory shape and public contract while gaining the discovery
mechanism. A follow-up change can consider a full dendritic layout if
the benefit becomes clear.

## Migration walkthrough for reviewers

1. Vendor + license (task 1-3).
2. Wire `_lib.importTree` (task 4).
3. Replace list files one at a time (tasks 5-8), running the full test
   matrix (`nix flake check` + BDD) after each replacement.
4. Decouple mkAdapter (task 9).
5. Dev-side discovery (task 10).
6. CI gate: assert no module is orphaned (task 11).
7. Update contributor docs (task 12).

At each step, the diff is small enough that `hunk diff --watch` in a
pane is the recommended review mode.

## Rollback plan

Revert the change. Because we do not add an input, there is no
lock-file churn to unwind for consumers. Contributors see the
hand-maintained lists reappear exactly as they were.

## Open questions to resolve before implementation

- **Q1**: Should the vendored `tests.nix` from upstream be included?
  Recommendation: yes, at `_lib/import-tree/tests.nix`, and wire it
  into the dev partition test aggregation. Cost is ~380 lines. Payoff:
  regression detection on any refresh.
- **Q2**: Should `_lib.importTree` be exposed via `_module.args` for
  all flake modules under `modules/nix-lib/`, or should each flake
  module `import ./_lib/import-tree` locally? Recommendation: expose
  via `_module.args.importTree` in `nix-lib-outputs.nix` so
  discoverers don't repeat imports.
- **Q3**: Is there a scenario where a consumer of `flakeModules.pure`
  would trigger `importTree` under `nix-lib.lib.docs.*` and fail? By
  D5 the pure filter excludes `docs/`, so no. Worth a test.
